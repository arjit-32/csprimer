## Algorithm Visualizer (`<AlgoVisualizer>`)

The **CSPrimer Algorithm Visualizer** renders step-by-step interactive animations for DSA problems, displaying executed code lines, tracking variables, highlighting cells, and animating pointers.

> [!TIP] Build with CMS Studio
> Rather than manually writing complex step arrays by hand, use the **CMS Visual Studio (`npm run admin`)**!
> 1. Open `http://localhost:4322` and go to **Tab 10: Problems Studio**.
> 2. Select **📊 Algorithm Visualizers** and click **➕ Create Problem** or click **✨ Visual Step Builder**.
> 3. Visually configure your steps, test live previews, and click **📋 Tag** to copy `<AlgoVisualizer problemId="..." />` directly into your article!

### 2. Complete TypeScript Schema Reference

All algorithm definition files reside in `src/problems/algorithms/<problem-slug>.ts` and export an object adhering to the schema below:

```typescript
// 1. Interactive Custom Input Field Schema
export interface InputSchema {
  name: string;        // Property key matching inputs[name] (e.g. "nums", "target")
  label: string;       // Form field label in the Customize drawer
  type: 'number' | 'string' | 'number-array' | 'string-array';
  defaultValue: any;   // Initial default value
  placeholder?: string;
  description?: string;
}

// 2. Array Element Highlight States
export interface ArrayHighlight {
  index: number;
  state: 'current' | 'match' | 'compare' | 'visited' | 'window' | 'found';
  label?: string;
}

// 3. Array State Structure
export interface ArrayState {
  values: (number | string)[];
  pointers?: Record<string, number> | { name: string; index: number; color?: string }[];
  highlights?: ArrayHighlight[];
  window?: [number, number]; // [startIndex, endIndex]
  label?: string;
}

// 4. Single Execution Step
export interface ExecutionStep {
  stepNumber?: number;
  title?: string;                  // Step header (e.g. "Calculate Midpoint")
  description?: string;            // Plain-English explanation of the action
  codeLine?: string;               // Idiomatic Java statement executed at this step
  variables?: Record<string, any>; // Key-value variable tracking bar
  array?: ArrayState;              // Single array state
  arrays?: ArrayState[];           // Multi-array state (e.g. Merge Sort)
  hashmap?: {
    entries: { key: any; value: any; state?: string }[];
    searchKey?: any;
    searchResult?: 'found' | 'not-found' | 'searching' | null;
  };
  set?: {
    elements: any[];
    searchElement?: any;
    searchResult?: 'found' | 'not-found' | 'searching' | null;
  };
  stack?: {
    items: any[];
    action?: 'push' | 'pop';
    label?: string;
  };
  queue?: {
    items: any[];
    action?: 'enqueue' | 'dequeue';
    label?: string;
  };
  deque?: {
    items: any[];
    action?: 'addFirst' | 'removeLast';
    label?: string;
  };
  tree?: {
    nodes: { id: string; value: any; left?: string; right?: string }[];
    rootId: string;
  };
  dpTable?: {
    grid: (number | string | null)[][];
    activeCell?: { row: number; col: number };
    formula?: string;
  };
}

// 5. Root Algorithm Definition
export interface AlgorithmDefinition {
  id: string;                       // Unique slug (e.g. "01-running-sum")
  title: string;                    // Problem title
  category?: string;                // Topic name (e.g. "Arrays", "Binary Search")
  difficulty?: 'Easy' | 'Medium' | 'Hard';
  description?: string;
  timeComplexity?: string;          // e.g. "O(N)"
  spaceComplexity?: string;         // e.g. "O(1)"
  visualizationTypes: ('array' | 'hashmap' | 'set' | 'stack' | 'queue' | 'deque' | 'tree' | 'dptable')[];
  defaultInputs: Record<string, any>;
  inputSchema: InputSchema[];
  generateSteps: (inputs: Record<string, any>) => ExecutionStep[];
}
```

### 3. File Code Boilerplate (`src/problems/algorithms/<slug>.ts`)

If you write or edit an algorithm manually, adhere to this clean structure:

```typescript
import type { AlgorithmDefinition, ExecutionStep } from './types';
import { StepBuilder } from './builder';

export const algoBinarySearch: AlgorithmDefinition = {
  id: 'sample-binary-search',
  title: 'Binary Search',
  category: 'Searching',
  difficulty: 'Easy',
  description: 'Halve the search space using low, mid, and high pointers along with an active subarray window.',
  visualizationTypes: ['array'],

  defaultInputs: {
    nums: [2, 5, 8, 12, 16, 23, 38, 56, 72, 91],
    target: 23,
  },

  inputSchema: [
    {
      name: 'nums',
      label: 'Sorted Array',
      type: 'number-array',
      defaultValue: [2, 5, 8, 12, 16, 23, 38, 56, 72, 91],
      description: 'Ascending sorted array',
    },
    {
      name: 'target',
      label: 'Target Value',
      type: 'number',
      defaultValue: 23,
      description: 'Number to search for',
    },
  ],

  generateSteps: (inputs: Record<string, any>): ExecutionStep[] => {
    // 1. Sanitize inputs safely to support custom inputs
    const rawNums = inputs.nums;
    const nums: number[] = Array.isArray(rawNums)
      ? rawNums.map(Number).filter((n) => !isNaN(n))
      : [2, 5, 8, 12, 16, 23, 38, 56, 72, 91];
    const target = Number(inputs.target ?? 23);

    const builder = new StepBuilder();

    if (nums.length === 0) {
      builder.step({ title: 'Empty Array', description: 'Search space is empty.', array: { values: [] } });
      return builder.build();
    }

    let low = 0;
    let high = nums.length - 1;

    // Step 0: Initial State
    builder.step({
      title: 'Initialize Search Space',
      description: `Target is ${target}. Candidate interval is [0..${high}].`,
      codeLine: 'int low = 0, high = nums.length - 1;',
      variables: { low, high, target },
      array: { values: [...nums], pointers: { low, high }, window: [low, high], label: 'nums[]' },
    });

    // Execution loop
    while (low <= high) {
      const mid = Math.floor((low + high) / 2);
      const midVal = nums[mid];

      builder.step({
        title: `Calculate Midpoint: mid = ${mid}`,
        description: `Inspect element at index ${mid} (${midVal}) vs target (${target}).`,
        codeLine: 'int mid = low + (high - low) / 2;',
        variables: { low, mid, high, 'nums[mid]': midVal, target },
        array: {
          values: [...nums],
          pointers: { low, mid, high },
          highlights: [{ index: mid, state: 'current' }],
          window: [low, high],
          label: 'nums[]',
        },
      });

      if (midVal === target) {
        builder.step({
          title: `Target Found at Index ${mid}!`,
          description: `nums[${mid}] == ${target}. Search succeeds.`,
          codeLine: 'if (nums[mid] == target) return mid;',
          variables: { mid, target, status: 'FOUND' },
          array: { values: [...nums], pointers: { mid }, highlights: [{ index: mid, state: 'match' }], label: 'nums[]' },
        });
        return builder.build();
      } else if (midVal < target) {
        low = mid + 1;
        builder.step({
          title: `nums[mid] < target: Narrow to Right Half`,
          description: `Advance low to ${low}.`,
          codeLine: 'low = mid + 1;',
          variables: { low, mid, high, target },
          array: { values: [...nums], pointers: { low, high }, window: [low, high], label: 'nums[]' },
        });
      } else {
        high = mid - 1;
        builder.step({
          title: `nums[mid] > target: Narrow to Left Half`,
          description: `Decrement high to ${high}.`,
          codeLine: 'high = mid - 1;',
          variables: { low, mid, high, target },
          array: { values: [...nums], pointers: { low, high }, window: [low, high], label: 'nums[]' },
        });
      }
    }

    builder.step({
      title: 'Target Not Found',
      description: `Search space exhausted without finding target.`,
      codeLine: 'return -1;',
      variables: { target, status: 'NOT FOUND' },
      array: { values: [...nums], label: 'nums[]' },
    });

    return builder.build();
  },
};

// Always provide default export for automatic dynamic imports
export default algoBinarySearch;
```

## TryCode: In-Browser JavaScript Drills

**TryCode** is CSPrimer's in-browser interactive code editor, powered by **Monaco Editor** and client-side execution sandboxes.

> [!NOTE] Scope
> - **TryCode is reserved strictly for frontend & JavaScript interview problems** (utility functions, DOM manipulation, asynchronous tasks, data transformations).
> - DSA / Java problems use the **Algorithm Visualizer (`<AlgoVisualizer>`)** on the previous tab.

---

### 1. How to Embed in MDX

```html

```

Or for DOM mode:

```html

```

### 2. File Location & TypeScript Schema

All TryCode problem definitions reside in `src/problems/frontend/<problem-slug>.ts`:

```typescript
export interface TestCase {
  input: any[];      // Array of arguments passed to solution(...)
  expected: any;     // Expected return value (deep equality comparison)
}

export interface Problem {
  id: string;                    // Unique slug matching the filename (e.g. "array-unique")
  title: string;                 // User-facing problem title
  mode: "function" | "dom";      // Execution mode
  starterCode: string;           // Initial code shown in the Monaco editor
  tests: TestCase[];             // Automated test suite
  html?: string;                 // Required if mode === "dom": Initial HTML layout
}
```

---

### 3. Execution Modes & Blueprints

#### Function Mode (`mode: "function"`)

Used for algorithmic JS functions and utility implementations. The test runner passes `test.input` as arguments to `solution(...)` and validates the return value against `test.expected`:

```typescript
import type { Problem } from "../../types/problem";

const arrayUnique: Problem = {
  id: "array-unique",
  title: "Deduplicate Cart Items While Preserving Order",
  mode: "function",

  starterCode: `function solution(cartItems) {
  // Return only the first-seen product IDs in order.
  return Array.from(new Set(cartItems));
}`,

  tests: [
    {
      input: [["sku-1", "sku-2", "sku-1", "sku-3", "sku-2", "sku-4"]],
      expected: ["sku-1", "sku-2", "sku-3", "sku-4"],
    },
    {
      input: [["sku-9", "sku-9", "sku-9"]],
      expected: ["sku-9"],
    },
  ],
};

export default arrayUnique;
```

#### DOM Mode (`mode: "dom"`)

Used for interactive UI problems (search filters, counters, modal widgets). Provides an `html` template and executes starter code that attaches listeners to the DOM:

```typescript
import type { Problem } from "../../types/problem";

const domCounter: Problem = {
  id: "dom-counter",
  title: "Filter Product Results by Search Term",
  mode: "dom",

  starterCode: `const searchInput = document.getElementById('search');
const cards = [...document.querySelectorAll('[data-name]')];

searchInput.addEventListener('input', (event) => {
  const query = event.target.value.trim().toLowerCase();
  cards.forEach((card) => {
    const name = card.dataset.name.toLowerCase();
    card.style.display = name.includes(query) ? 'flex' : 'none';
  });
});`,

  html: `
    <div id="app" style="font-family: system-ui, sans-serif; max-width: 620px; margin: 0 auto; padding: 20px;">
      <div style="margin-bottom:16px;">
        <label for="search" style="display:block; margin-bottom:8px; font-weight:600;">Search products</label>
        <input id="search" type="text" placeholder="Search by product name" style="width:100%; padding:12px; border:1px solid #d1d5db; border-radius:8px;" />
      </div>
      <div style="display:grid; gap:12px;">
        <div data-name="Apple iPhone 15 Pro" style="display:flex; justify-content:space-between; padding:12px; border:1px solid #e5e7eb; border-radius:8px;">
          <span>Apple iPhone 15 Pro</span><strong>$999</strong>
        </div>
      </div>
    </div>
  `,

  tests: [{ input: [], expected: null }],
};

export default domCounter;
```

## Local Tooling, CMS Studio & Architecture

To avoid manual JSON edits and frontmatter mistakes, use the CSPrimer local development tools:

---

### 1. The Visual Content Studio (`npm run admin`)

Run the local Dev Studio dashboard alongside your Astro dev server:

```bash
npm run admin
```

Open **`http://localhost:4322`** in your browser.

- **Tab 1: Course Series Cards**: Interactive card grid of all courses to set status (`🟢 Live`, `⏳ In Progress`, `🔒 Planned`), edit metadata, and reorder.
- **Tab 2: Syllabus & Lessons**: Drag-and-drop chapter and lesson reordering, status toggles, and detection of unassigned lesson files.
- **Tab 3: Create Lesson / Project**: Smart switcher between **Course Lesson**, **Hands-on Project** (surfaced on `/articles`), and **Standalone Deep Dive**.
- **Tab 4: Reorder Roadmaps**: Visual track manager to reorder courses along learning paths with 1-click weight synchronization.
- **Tab 10: Problems Studio**: Manage **Algorithm Visualizers** with the **Visual Step Builder** and **TryCode exercises** with 1-click article tag insertion.

---

### 2. Terminal CLI (`npm run scaffold`)

Run the zero-dependency terminal assistant:

```bash
npm run scaffold
# or
npm run create
```

Follow the prompts to:
1. Create a new Course Series and register it into `roadmapOrder.json`.
2. Create a new Article (standalone or attached to a course syllabus).
3. Add an existing Series to a Roadmap category.

---

### 3. Platform Hierarchy & Metadata Rules

The platform organizes content in a 3-tier hierarchy:

> **Category (Track)** ➔ **Series (Course)** ➔ **Articles (Lessons)**

| Level | Where Configured | Purpose |
| :--- | :--- | :--- |
| **1. Category / Track** | `src/config/roadmapOrder.json` | Top-level learning domain (`Core-CS`, `DSA`, `Development`, `System-Design`, `AI-Engineering`). |
| **2. Series / Course** | `src/content/series/<id>.json` | Structured course with a syllabus (`navbar`). Defines `"category": "<Track>"`. |
| **3. Lessons** | `src/content/articles/<slug>.md` | The actual lessons. Linked via `series: "<id>"`. |
| **Standalone Articles** | `src/content/articles/<slug>.md` | Independent tutorials or build projects. **Omit `series`**; categorized via `categories: [...]`. |

---

### 4. Pre-Publish Checklist

Before submitting a pull request:

- [ ] **Frontmatter Validation**: Ensure `title` and `description` are non-empty strings.
- [ ] **Metadata Consistency**: If `series` is set, ensure it exists in `src/content/series/<id>.json`. If standalone, ensure `categories` contains valid tracks.
- [ ] **Visual Elements**: Verify that components use valid props (`<Notice type="...">`, `<Badge variant="...">`).
- [ ] **Local Build Check**: Run `npm run build` locally to verify that all pages compile without errors.
