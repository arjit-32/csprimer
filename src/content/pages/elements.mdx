## 2. Architecture & Metadata Rules

### The Core Hierarchy

The platform organizes content in a 3-tier hierarchy:

> **Category (Track)** ➔ **Series (Course)** ➔ **Articles (Lessons)**

| Level | Where Configured | Purpose |
| :--- | :--- | :--- |
| **1. Category / Track** | `src/config/roadmapOrder.json` | Top-level learning domain (`Core-CS`, `DSA`, `Development`, `System-Design`, `AI-Engineering`). |
| **2. Series / Course** | `src/content/series/<id>.json` | Structured course with a syllabus (`navbar`). Defines `"category": "<Track>"`. |
| **3. Lessons** | `src/content/articles/<slug>.md` | The actual educational lessons. Linked via `series: "<id>"`. |
| **Standalone Articles** | `src/content/articles/<slug>.md` | Independent tutorials or build projects. **Omit `series`**; categorized via `categories: [...]`. |

### Important Metadata Rules

1. **Course Lessons (`series` is set)**:
   - When an article has `series: "docker"`, its learning category is **inherited directly from the parent course**.
   - Lessons are grouped in the course syllabus and do not clutter the general `/articles` project listing.
2. **Standalone Articles (`series` is omitted)**:
   - Must specify `categories` using one or more of the 5 canonical categories below.
   - These are surfaced on `/articles` (Projects & Deep Dives).
3. **The 5 Canonical Categories**:
   - `"Core-CS"`: Operating systems, computer networks, computer architecture, databases, compilers.
   - `"DSA"`: Data structures, algorithms, complexity analysis, interview problem sets.
   - `"Development"`: Frontend, backend, fullstack frameworks, APIs, databases, tooling.
   - `"System-Design"`: Distributed systems, microservices, cloud architectures, scalability.
   - `"AI-Engineering"`: Machine learning, LLM integrations, embeddings, AI agents.

## 3. Step-by-Step Creation Playbooks

<Tabs>

<Tab name="1. Standalone Article">

### Adding a Standalone Article or Project

Use this for single-topic deep dives, project write-ups, or tutorials that do not belong to a sequential course syllabus.

#### Step 1: Create the markdown or MDX file
Create `src/content/articles/<your-article-slug>.md` (or `.mdx` if using custom components).

#### Step 2: Add Frontmatter
> **Important**: Do not add the `series` key for standalone articles.

```yaml
---
title: "Building an LRU Cache from Scratch in TypeScript"
description: "Learn cache eviction policies by implementing a doubly linked list + hash map cache."
categories: ["Development"]
author: "Arjit Sharma"
draft: false
featured: false
---
```

#### Step 3: Write Content
Write in standard Markdown or import MDX components (e.g. `<Notice>`, `<Badge>`, `<Accordion>`).

</Tab>

<Tab name="2. Course / Series">

### Adding a Multi-Lesson Series

A course requires connecting series metadata with lesson articles and roadmap ordering.

#### Step 1: Create the Series JSON
Create `src/content/series/<course-id>.json`.

```json
{
  "title": "System Design Essentials",
  "subtitle": "Architecting Scalable and Resilient Web Services",
  "description": "Learn load balancing, horizontal scaling, caching strategies, and data consistency models.",
  "category": "System-Design",
  "image": "../../assets/images/thumbnails/system-design.png",
  "weight": 10,
  "navbar": [
    {
      "subheading": "1. Foundations",
      "link": [
        { "type": "articles", "url": "intro-system-design", "title": "Introduction to System Design", "status": "in-progress" },
        { "type": "articles", "url": "load-balancing-basics", "title": "Load Balancing Patterns", "status": "planned" }
      ]
    }
  ]
}
```

*Status options*: `"planned"` (locked), `"in-progress"`, or `"re-visiting"`.

#### Step 2: Create the Lesson Articles
For each item in `navbar.link`, create the corresponding file in `src/content/articles/<url>.md`.
Ensure the `series` frontmatter value exactly matches `<course-id>`:

```yaml
---
title: "Introduction to System Design"
author: "Arjit Sharma"
series: "system-design-essentials"
categories: ["System-Design"]
draft: false
---
```

#### Step 3: Register in Roadmap Ordering
Open `src/config/roadmapOrder.json` and append `<course-id>` under the corresponding category array:

```json
{
  "System-Design": [
    "aws",
    "distributed",
    "system-design-essentials"
  ]
}
```

*(Or simply run `npm run admin` to perform all 3 steps automatically).*

</Tab>

<Tab name="3. Short">

### Adding a Short Concept Video

Shorts are bite-sized concept explainers linked to a YouTube short or micro-video.

#### Step 1: Create the Short File
Create `src/content/shorts/<series-name>/<slug>.md`.

#### Step 2: Set Frontmatter

```yaml
---
title: "What is Database Sharding?"
youtubeId: "dQw4w9WgXcQ"
series: "dbms-shorts"
seriesName: "Database Systems"
order: 1
---
```

#### Step 3: Body Text
Optionally include a 2-3 paragraph summary or quick reference bullets below the frontmatter.

</Tab>

<Tab name="4. Interview Byte">

### Adding an Interview Question

Interview questions power the **Interview Bytes** explorer and the **Anki Revision Modal**.

#### Step 1: Open or Create the Category YAML
Locate or create `src/content/interview-questions/<topic>.yaml` (e.g. `javascript.yaml`, `nodejs.yaml`).

#### Step 2: Append Question Entry

```yaml
questions:
  - id: 101
    tags: [javascript, closures, async]
    question: "Explain the Event Loop microtask vs macrotask execution order."
    answer:
      - "Synchronous code executes first on the call stack."
      - "Microtask queue (Promise callbacks, queueMicrotask) is completely drained before rendering."
      - "Macrotask queue (setTimeout, setInterval, I/O) executes one task per tick followed by microtasks again."
    code: |
      console.log('1');
      setTimeout(() => console.log('2'), 0);
      Promise.resolve().then(() => console.log('3'));
      console.log('4');
      // Output: 1, 4, 3, 2
```

</Tab>

<Tab name="5. TryCode Exercise">

### Adding an Interactive TryCode Coding Problem

TryCode embeds an in-browser code editor and automated test runner.
> <Notice type="warning">TryCode is strictly reserved for frontend JavaScript/TypeScript interview problems. Do not use for DSA theory or compiled languages.</Notice>

#### Step 1: Create Problem Definition
Create `src/problems/frontend/<problem-id>.ts`:

```typescript
const problem = {
  id: "array-unique",
  title: "Remove Duplicates While Preserving Order",
  starterCode: `function solution(nums) {\n  // Write your code here\n  return [];\n}`,
  tests: [
    { input: [[1, 2, 2, 3, 1, 4]], expected: [1, 2, 3, 4] },
    { input: [[5, 5, 5]], expected: [5] }
  ]
};

export default problem;
```

#### Step 2: Embed in any MDX Article

```mdx
<TryCode problemId="array-unique" />
```

</Tab>

<Tab name="6. Roadmap Track">

### Adding or Updating a Roadmap Category

When introducing a new major learning track (e.g., `AI-Engineering`), synchronize these files:

1. **`src/config/roadmapOrder.json`**: Add the new key with its list of series IDs.
2. **`src/content/series/<id>.json`**: Set `"category": "AI-Engineering"`.
3. **`src/pages/roadmaps.astro`**: Add category tab and filter badge.
4. **`src/pages/courses/index.astro`**: Add category filter button.
5. Update the supported categories list in this document and optionally in `src/content/articles/-index.md`.

</Tab>

## 4. Complete Schemas & Type Reference

This section provides the static field definitions, types, defaults, and allowed values for every content collection defined in `src/content/config.ts`.

### 4.1 Articles Collection Schema
**Location:** `src/content/articles/*.md` or `*.mdx`  
**Purpose:** Standalone articles, project tutorials, and course lessons.

| Field | Type | Required | Default | Allowed Values / Constraints | Description |
| :--- | :--- | :---: | :--- | :--- | :--- |
| `title` | `string` | **Yes** | — | Non-empty string | Article title shown in headings and cards |
| `subtitle` | `string` | No | `undefined` | Any string | Secondary subhead for lessons or deep dives |
| `meta_title` | `string` | No | `undefined` | String (≤ 60 chars recommended) | SEO `<title>` tag override |
| `description` | `string` | No | `undefined` | String (≤ 160 chars recommended) | Meta and OpenGraph description |
| `image` | `string` | No | `undefined` | Relative path (e.g. `/images/og-image.jpg`) | Card thumbnail and social share preview |
| `author` | `string` | No | `undefined` | e.g. `"Arjit Sharma"` | Content author |
| `series` | `string` | No | `undefined` | Filename of series in `src/content/series/` | Links lesson to a course. **Omit for standalone articles** |
| `categories` | `string[]` | No | `["others"]` | `Core-CS`, `DSA`, `Development`, `System-Design`, `AI-Engineering` | Subject classification tag |
| `draft` | `boolean` | No | `false` | `true`, `false` | Excludes article from production builds when `true` |
| `year` | `number` | No | `undefined` | 4-digit year (e.g. `2025`) | Publishing / revision year |
| `featured` | `boolean` | No | `false` | `true`, `false` | Highlighted in hero card carousel |

#### TypeScript Interface
```typescript
export interface ArticleFrontmatter {
  title: string;
  subtitle?: string;
  meta_title?: string;
  description?: string;
  image?: string;
  author?: string;
  series?: string;
  categories: ("Core-CS" | "DSA" | "Development" | "System-Design" | "AI-Engineering" | "others")[];
  draft?: boolean;
  year?: number;
  featured?: boolean;
}
```

### 4.2 Series / Course Collection Schema
**Location:** `src/content/series/<course-id>.json`  
**Purpose:** Course metadata, syllabus chapters, and sidebar navigation hierarchy.

| Field | Type | Required | Default | Allowed Values / Constraints | Description |
| :--- | :--- | :---: | :--- | :--- | :--- |
| `title` | `string` | **Yes** | — | Non-empty string | Course display title |
| `subtitle` | `string` | No | `undefined` | Any string | Course tagline |
| `description` | `string` | **Yes** | — | Any string | Course summary on course overview cards |
| `image` | `string` | No | `undefined` | Path to thumbnail | Cover banner image |
| `category` | `string` | No | `"Course"` | `"Core-CS"`, `"DSA"`, `"Development"`, `"System-Design"`, `"AI-Engineering"` | Learning track bucket |
| `ongoing` | `boolean \| string` | No | `false` | `true`, `false`, `"On-going"` | Indicates course is actively receiving updates |
| `status` | `string` | No | `undefined` | `'planned'`, `'in-progress'`, `'re-visiting'` | Global course progress status |
| `time` | `string` | No | `undefined` | e.g. `"4 hours"`, `"12 lessons"` | Estimated completion time |
| `weight` | `number` | No | `100` | Integer | Sort weight (lower appears first) |
| `navbar` | `Array<Section>` | **Yes** | — | Array of syllabus sections | Ordered chapters and lesson links (see below) |

#### Navbar Structure (`navbar`)
Each section inside `navbar` contains:
- `subheading`: `string` (e.g. `"1. Foundations"`)
- `link`: Array of lesson links:
  - `type`: `"articles"` | `"external"`
  - `url`: `string` (article slug in `src/content/articles/` without `.md`, or external URL)
  - `title`: `string` (lesson title)
  - `status`: `'planned'` | `'in-progress'` | `'re-visiting'` (optional; `'planned'` displays a lock icon)

#### TypeScript Interface
```typescript
export type CourseStatus = 'planned' | 'in-progress' | 're-visiting';

export interface SeriesNavbarLink {
  type: 'articles' | 'external';
  url: string;
  title: string;
  status?: CourseStatus;
}

export interface SeriesNavbarSection {
  subheading: string;
  link: SeriesNavbarLink[];
}

export interface SeriesData {
  title: string;
  subtitle?: string;
  description: string;
  image?: string;
  category: string;
  ongoing?: boolean | string;
  status?: CourseStatus;
  time?: string;
  weight: number;
  navbar: SeriesNavbarSection[];
}
```

### 5.4 Accordions (`<Accordion>`)

Expandable accordion container for FAQs, solutions, or deep-dive collapsible explanations.

<Accordion title="When should I use a Series instead of a Standalone Article?">

Create a **Series** when:
- The content consists of multiple sequential lessons or chapters.
- You need a persistent sidebar navigation and previous/next chapter progression.
- The course belongs to a categorized learning path on `/roadmaps`.

Create a **Standalone Article** when:
- It is a single project, quick tutorial, or independent deep dive.
- It does not require a sidebar syllabus.

</Accordion>

<Accordion title="How do I mark a lesson as planned/locked in a course?">

In `src/content/series/<id>.json`, set `"status": "planned"` on the link object:

```json
{
  "type": "articles",
  "url": "distributed-consensus",
  "title": "Distributed Consensus (Raft & Paxos)",
  "status": "planned"
}
```

This displays the lesson with a lock icon and disables navigation until it is published.

</Accordion>

#### Usage Code

```mdx
<Accordion title="Your Accordion Title Here">
  Your collapsible explanation, code snippets, or list items go here.
</Accordion>
```

### Pre-Publish Checklist

Before committing or pushing new content:

- [ ] File created in the designated folder (`articles/`, `series/`, `shorts/`, etc.).
- [ ] Frontmatter strictly validated against the schemas in [Section 4](#4-complete-schemas--type-reference).
- [ ] Category chosen from the 5 canonical values (`Core-CS`, `DSA`, `Development`, `System-Design`, `AI-Engineering`).
- [ ] `series` field matches the exact JSON course ID (if part of a course).
- [ ] `roadmapOrder.json` updated with new series ID (handled automatically by `npm run admin` / `npm run scaffold`).
- [ ] `draft: false` set for all live content.
