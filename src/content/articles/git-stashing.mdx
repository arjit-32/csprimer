Stashing allows you to **save uncommitted changes temporarily** and restore them later. This is useful when you are interrupted and need to switch tasks or branches without committing half-finished work.

## 1. Basic Stashing Workflow

```text
[do some work]
[get interrupted]
git stash
[deal with interruption]
git stash pop
```

When an urgent bug fix interrupts your feature work, shelve your uncommitted work with `git stash`:

```bash
git stash
git status
git log --graph --all --oneline
```

After handling the urgent task, pop your changes back:

```bash
git stash pop
```

## 3. Managing Multiple Stashes

Git keeps multiple stashes in a LIFO (Last-In, First-Out) stack:

```bash
# List all saved stashes
git stash list

# Inspect what changes are inside a stash:
git stash show --patch stash@{0}
git stash show --patch stash@{1}
```

<GitVisualizer scenario="stash-stack" title="Managing Multiple Stashes (LIFO Stack)" />

### Applying vs Popping
- **`git stash pop`**: Reapplies the most recent stash (`stash@{0}`) and **removes it** from the stack.
- **`git stash apply stash@{1}`**: Reapplies a specific stash but **keeps it on the stack**.

---

## 4. Deleting Stashes

```bash
# Drop a specific stash
git stash drop stash@{0}

# Remove all stashes completely
git stash clear
```

---

## 5. Stashing Untracked Files

By default, `git stash` only stores tracked files. To include untracked new files, use `-u`:

```bash
# Include untracked files
git stash -u

# Include all files, including those in .gitignore
git stash --all
```
